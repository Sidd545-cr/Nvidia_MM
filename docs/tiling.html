How one thread block computes its tile of C

The block loads a TILE×TILE piece of A and of B into shared memory, waits, does TILE multiply-adds per thread from shared memory, waits again, and moves one tile along the inner dimension. Step through it with the arrow keys. Click any cell of C to pick a different thread or block.

What to take away

Reuse. In the naive kernel every thread reads its own row of A and column of B from global memory, so each element of A is fetched once per thread that needs it. Here each element is fetched from global memory once per block and then read TILE times from shared memory. Global reads drop by a factor of TILE, which the counter shows (4× here, 16× or 32× with real tile sizes).

Two barriers per phase. The first __syncthreads() stops anyone reading the tile before every thread has written its element. The second stops anyone overwriting the tile with the next phase before every thread has finished reading it.

Edges. When M, N or L is not a multiple of TILE, the last tiles stick out of the matrix. Those slots are filled with 0, so the extra multiply-adds add nothing, and threads outside M×L compute but skip the final store. Switch to the irregular size to see both.

Still coalesced. During a load, neighbouring tx read neighbouring columns of one row of A and of B, the same pattern as the naive kernel's B reads.
